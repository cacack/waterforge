# CONSTITUTION.md Drift Report — 2026-09-11

Existing constitution last refreshed: 2026-05-31

## Summary

Alignment is strong: the mission, audience, and all four non-goals still
describe what Waterforge is, and the commit log shows no scope violations. The
drift is of a different kind — the project **shipped past its constitution**
(carbonation as a second modelling axis, offline/installable delivery) and then
**changed phase** (feature-complete since v1.5.0; the last three months are
dependency, CI, and site-health work). The success criteria are all met and now
read as a finished build-out checklist with nothing to say about sustained
maintenance.

## Drift findings

### [MAJOR] Carbonation is a shipped axis the mission doesn't name

- **Section:** Mission
- **Current text:** "takes a target water profile, subtracts what's already in
  your source water, and computes the exact salt additions needed to hit it"
- **Evidence of drift:** Carbonation is now first-class in the engine, the data
  model, and the UI — `src/lib/chem/carbonation.ts` (forced-carbonation math,
  volumes ↔ g/L ↔ regulator psi), `src/components/CarbonationSection.svelte` and
  `CarbonationReadout.svelte`, `carbonation_style` / `carbonation_target` profile
  fields ([ADR 0013](../../decisions/0013-still-sparkling-and-carbonation-target.md)),
  `docs/guides/chemistry.md` §2, and `USAGE.md` §Carbonation plus "Step 6 —
  Dissolve and (optionally) carbonate". The module's own header calls it "the
  carbonation analogue of the ion engine … an orthogonal axis to ion matching."
  The mission describes only the ion/salt axis.
- **Proposed update:** Extend the mission's second sentence to name both axes —
  after "…the exact salt additions needed to hit it", add: "and, for a sparkling
  target, the regulator pressure to carbonate it to match".

### [MAJOR] Offline / installable delivery isn't captured

- **Section:** Principles (5)
- **Current text:** "**Static and client-side over backend convenience** —
  everything runs in the browser. No servers, accounts, or telemetry: cheaper to
  host, private by default, durable."
- **Evidence of drift:** `vite-plugin-pwa` is a shipped runtime dependency
  (`package.json` `dependencies`), configured in `vite.config.ts`. README leads
  with it: "Install it to your home screen and it works offline, at the counter,
  with no connection." This is a deliberate delivery property — usable at the
  counter with no signal — that the principle's "durable" gestures at but never
  claims.
- **Proposed update:** Extend the principle's elaboration: "No servers,
  accounts, or telemetry: cheaper to host, private by default, durable — and
  installable, so it keeps working offline at the counter."

### [MINOR] The hosting criterion names the mechanism, not the outcome

- **Section:** Success Criteria
- **Current text:** "The app is live and usable at a public URL (GitHub Pages),
  no install required."
- **Evidence of drift:** GitHub Pages is still the origin, but the site is served
  at the custom domain **waterforge.app** fronted by a CloudFlare proxy (CDN +
  WAF), with its own failure modes and runbook
  ([docs/operations/cloudflare-pages.md](../../operations/cloudflare-pages.md))
  and a daily site-health check (commit `bf50f91`, `48d53b6`). Naming one hop of
  a multi-hop delivery path dates the constitution; the ops docs are the
  authoritative home for the mechanism.
- **Proposed update:** "The app is live and usable at
  [waterforge.app](https://waterforge.app), no install required — and installable
  for offline use."

### [MINOR] "Seed library" framing is stale, and the category list is incomplete

- **Section:** Success Criteria
- **Current text:** "A seed library of the planned bottled/brewing/coffee target
  profiles ships and is browsable. The library may grow beyond the Lersch/Khymos
  seed…"
- **Evidence of drift:** The grow-beyond-the-seed work is done — issue #98
  ("Expand the bottled-water library beyond the Khymos seed set") closed
  2026-06-01. `src/lib/profiles/profiles.json` now carries **54 profiles across
  14 countries**: 45 bottled, 4 brewing, 3 **synthetic**, 2 coffee. The
  constitution's three-category list omits `synthetic`, and "seed" now describes
  a past state rather than the criterion.
- **Proposed update:** "A browsable library of sourced target profiles ships —
  bottled, brewing, coffee, and synthetic references. It grows opportunistically,
  with every new profile held to the same authoritative-sourcing standard (see
  ADR 0011)."

### [MINOR] Success criteria say nothing about the maintenance phase the project is in

- **Section:** Success Criteria
- **Current text:** all four criteria describe reaching a feature-complete state.
- **Evidence of drift:** `ROADMAP.md` states "Waterforge is feature-complete
  against its mission. As of v1.5.0 all four success criteria are met."
  Everything since — v1.9.0 → v1.9.4, and effectively the entire commit log since
  2026-05-31 — is dependency currency, CI hardening, and uptime work: CVE
  clearing (`7c691b3`, `687b799`), Node 24 LTS (`8ba630b`), daily CI on main
  (`e14383a`), site-health alerting (`bf50f91`, `48d53b6`). With every stated
  criterion met, the constitution offers no way to tell whether the project is
  still healthy.
- **Proposed update:** Add a fifth criterion: "Once feature-complete, it stays
  that way: the site is up, dependencies stay current, and security advisories
  are cleared promptly — a released version is always installable and correct."

## Sections still accurate

- **Audience** — both halves hold. The "not for" line is actively defended: the
  repo has no mash-pH or residual-alkalinity code, and `ROADMAP.md` re-states
  the boundary under "Not planned".
- **Non-Goals** — all four still hold. The carbonation work does **not** breach
  "predict flavor or sensory outcomes": `carbonation.ts` computes regulator
  pressure from physics, not taste.

  **Correction (added 2026-09-11, post-panel):** an earlier draft of this report
  also cited ADR 0013's "Unset is the honest default; targets are not estimated"
  as evidence here. That is ADR 0013's _text_, but no longer the shipped state —
  issue #132 populated `carbonation_target` on five profiles, and four (Perrier,
  Badoit, San Pellegrino, Topo Chico) are `verified: false` and self-labelled
  "Estimate" in `src/lib/profiles/profiles.json`. The non-goal conclusion is
  unaffected; the supporting evidence was stale. See the Trust Auditor's findings
  in `docs/reviews/panel-product/2026-09-11/trust.md` — the policy reversal was
  never recorded as an ADR amendment, unlike the ADR 0001 → 0012 precedent.

- **Principles 1–4** — unchanged and observably followed. Two recent decisions
  are direct evidence: issue #27 (teaspoon / volume salt-measure mode) was closed
  **not planned**, upholding principle 3 (precision over hand-waving); and
  ADR 0013 routes a new unit vocabulary through explicit converters "cf. the
  as-CaCO₃ / as-HCO₃ discipline", upholding the same principle in code.
- **Principle 1 (free and copyleft)** — intact: split GPLv3 / CC-BY-SA-4.0 still
  in `LICENSE` / `LICENSE-DATA`, per-profile sourcing per ADR 0012.

## Suggested additions

- **A maintenance-phase success criterion** — see the [MINOR] finding above. This
  is the single most useful addition: it is the only proposed change that gives
  the constitution something to measure in the phase the project is actually in.
- **No new principles or non-goals proposed.** The five principles still
  constrain real decisions and the four non-goals are still being enforced;
  adding to either would be noise.
